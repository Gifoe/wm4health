# C53 runtime adaptation and completed-attempt accounting

The native PatchTST frozen-AE concat configuration reached31,713 MiB GPU usage with474 MiB free and about60s per epoch on the single32GB device. The incomplete seed0 attempt was deliberately stopped after its observed resource saturation. Its initial weights/curve/log/state are retained; it supplies no selected checkpoint and is excluded from completed fits. This was a controlled resource repair, not a response to an observation timeout or transfer score. The subsequent Gate fit was allowed to complete unchanged.

The Win32 termination API returned process exit0 when no explicit reason code was supplied. The old exit-code-only supervisor therefore advanced despite the missing native terminal files. The old supervisor was explicitly stopped; no result is accepted on that status alone. The active supervisor requires native state COMPLETE, a summary, an existing selected checkpoint and its matching SHA before reusing or completing any job.

Two runtime alternatives were measured and rejected: saved-tensor CPU storage preserved the checked update but cost27.38s for one native128-sample update; nonreentrant buffer-free encoder checkpointing exceeded the28GiB qualification threshold (35,436,825,088 allocated bytes). Neither was used for a formal completed fit.

The adopted adaptation applies only to PatchTST + AE concat: original full128-sample batches and their CPU shuffle order are retained, each is split into two64-sample forwards, weighted MSE gradients accumulate, and clipping/Adam execute once per original full batch. No AMP, data truncation or selection-rule change. The architecture has no batch normalization or cross-sample prediction interaction. Validation and other configurations retain their original native implementation.

This is not bitwise equivalence. The small deterministic comparison (dropout disabled in that qualification only) gave loss difference7.45e-9, maximum parameter-update difference4.09e-4 and post-update prediction difference6.02e-6. The first strict parameter-difference check failed and is retained. A second qualification records these numerical differences and checks the post-update function. Formal dropout remains enabled and iid, but GPU draw ordering differs between full and split batches. The adapted arm must be described as a source-protocol reproduction with a disclosed memory adaptation, rather than identical original-run weights. The full128-sample qualification update used21,405,701,632 allocated bytes and0.5233s; this single preflight is not a publishable throughput benchmark.

Active trainer: train_native53_v5.py; supervisor: capture_native53_v5.py; selected identities: SELECTION_SEAL_V5.json; evaluation: score_native53_v6.py. All native upstream Python files remain unchanged. Previously completed native fits are reused only after terminal-file/checkpoint verification. The stopped attempt is not a warm start; its initial tensors must match the restarted seed0 initialization before training. No second-batch score has been opened.
