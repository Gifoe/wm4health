# Ordinary inference implementation controls

Frozen before inspecting C29 independent model-test scores. This is an implementation control, not a new method or additional training. Main scientific sources and their queued source locks remain unchanged.

The C29 eager latency measures a particular implementation. It cannot establish that a generated operator has a fundamental latency advantage over ordinary context conditioning. At a fixed context, the conditional GRU input contribution from its 64-dimensional code is constant. Fold this term into `bias_ih`, retaining all three GRU gates. For the compiled GRU, merge the generated recurrent update into `weight_hh`. Both then use the existing PyTorch `nn.GRU` sequence implementation over a batch of candidate input plans, with one shared initial state and system for that batch. No compilation or parameter adaptation uses future outputs.

For the source attention simulator, retain its already cached encoder memory. A second ordinary control disables unused attention-weight output (`need_weights=False`) to permit PyTorch SDPA; no weights, attention mask, positional encoding or context is changed. This is not training and is not an architecture contribution. Further KV caching or graph compilation could still change runtimes; this comparison establishes no universal lower bound.

Run only after the existing training, main evaluation/verification and real-transfer queue have terminated successfully, without concurrent experiment GPU work. Use the validation recordings, never independent TEST, for implementation verification and speed measurement. Select the first two validation systems in each of LTI and WH, all three predeclared seeds, horizons 32 and 128, and 1/16/64 candidate plans. Candidate future input sequences are deterministic circular shifts of a validation input segment; only shapes and implementation equivalence are at issue. The last horizon128 samples may exceed training horizon32, but no accuracy metric or validation selection uses these results.

Report context encoding, parameter preparation, and cached simulation separately, including preparation in the one-use and 64-use amortized totals. Keep original eager and ordinary optimized versions. After 3 warm-up calls, time 9 synchronized trials; report medians, p10 and p90, with the runtime/GPU information and cuDNN settings. FP32, TF32 disabled, same allowed input information. There is no best-case selection by seed/system/horizon.

Before timing, independently reproduce a nonzero generated GRU step and the folded-code GRU step using the PyTorch `GRUCell` operator. Then verify whole-sequence eager vs fused, and source attention vs SDPA, with atol2e-4 and rtol2e-4. Record actual maxima. A failure stops the job; do not weaken tolerances to complete it. Trainable weights and original prediction artifacts are not modified. These comparisons concern finite precision equality and deployment cost, not forecasting accuracy or physical validity.

Outputs live separately in `outputs/inference_controls_v1/`. A failed control cannot invalidate previously independently verified scores from unchanged inference paths, but it blocks any optimized-runtime claim.
