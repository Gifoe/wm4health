# Closest-work and source boundary, C83

Primary papers and actual source were inspected on 2026-10-18. Public code copies and hashes are retained on server only in SOURCE_AUDIT83_V1.json. Code availability is distinct from reproduction; none of these three ICON repositories has been executed in C83.

| Work | Relevant contract | Consequence for this research |
| --- | --- | --- |
| [UNICON](https://arxiv.org/html/2607.28432v3), v3 Aug12 | Graph/entity/channel structured in-context operator inference, history keys and future-state values, same operator/lead within a context, mixed-source pretraining; demonstrated tasks are forecasting | A general graph-conditioned pretrained predictor already exists. | [OpenFIM / FIM-ODE](https://arxiv.org/html/2602.08733v2) | Low-dimensional pretrained ODE field inference, normalization, noisy trajectories; higher-dimensional work is discussed as a limitation | C83 is a cross-contract use of the unchanged checkpoint through known target parent sets. ## Actual public source

- [icon-chop at85715f186082b2830fd62e66725ed4c0e10e89e4](https://github.com/scaling-group/icon-chop/tree/85715f186082b2830fd62e66725ed4c0e10e89e4):459 files. Four checkpoint files are explicitly present (two regional GICON checkpoints about9.6MB each; conservation/MFC checkpoints about57.3MB each). Data generation and saved evaluations exist. No large source-data or checkpoints were downloaded during this availability audit.
- Its actual `eval/conservation_law/multistep_eval.py` fixes the first five transitions as demonstrations, starts from frame5, recursively feeds predictions for default10 steps. The visible target is used for metrics, not the next input. Actual WENO `chains.py` is a fixed scale/shift/mass chain and explicitly has no selector or parametric residual estimator. Thus the paper's general discussion of candidate stacking must not be misreported as a component of this particular WENO implementation.
- Its graph-in-context README/evaluator specifies direct+delta prediction on2023 with2016–2022 contexts, five demonstrations,24-frame windows, random/retrieval contexts. The shared GICON call forwards data and graph. This is a direct forecast protocol, not an intervention-ground-truth benchmark.
- [icon-core at ef27409e38d9088565d40ea562c70de31ed7adc1](https://github.com/scaling-group/icon-core/tree/ef27409e38d9088565d40ea562c70de31ed7adc1):146 files; ICON/VICON infrastructure and model/config paths. No inference that this infrastructure alone supplies a verified UNICON checkpoint. Availability audit records the tree rather than pretending missing guessed filenames imply missing code.
- [icon-tutorial at f8404c0edca7cca7f767c3562ade51d66b222d5d](https://github.com/scaling-group/icon-tutorial/tree/f8404c0edca7cca7f767c3562ade51d66b222d5d):35 files; numerical-prompt autoregressive conservation-law ICON implementation, earlier tutorial rather than proof of a released UNICON model.

## Claim limits and challenges

C83 can establish a scoped positive or negative capability result for local reuse. It cannot establish that composing local models is novel: modular meta-learning, graph models and compositional operators predate this screen. Known parent sets and full physical coordinates remove latent identification difficulty deliberately. A successful simulation would still require unknown-mechanism/size/observation transfer and actual matched graph/operator baselines before a new time-series world-model claim. A failure with similar context field fit would motivate diagnosing accumulated field errors and support departure; neither is automatically a new gap. C82 already showed that an open neighborhood does not inevitably prevent accurate target-field inference.

No author-reported results were entered as our reproduced metrics. Source inspection is not a native baseline run. Primary-paper summaries above are concise paraphrases, not copied text.
