# Reproduction contract

Use a new project/output directory; completed fits, logs and seals are immutable. Python 3.10 and the pinned CPU runtime versions are recorded in `outputs/preflight54.json`. Obtain the exact upstream commit specified in `plan54_v1.json`, and verify its 21 listed file hashes. The native package's public license and dependency constraints remain applicable.

The scripts expect this project layout: `cycle54/`, `upstream/rp-gssm/`, and parent `STORAGE_LOCATION_V1.json` with `data_root`, `checkpoint_root`, `artifact_root` and `cache_root`. All data, checkpoints, and numeric arrays are written below these configured roots in `cycle54/`; compact logs/metrics/reports are under the experiment directory. The executed common module also applies a Windows CPU affinity mask for eight logical processors. Portability to another operating system is not claimed without adapting that operating-system-specific runtime limit.

Execution order is `prepare54.py`, then each `train54.py METHOD TASK SEED` (`rp` and `em`; the two configured tasks; seeds 0,1,2). `supervise54.py` executes exactly that queue and writes the immutable all-fit selection seal. Official runs use `start54_v3.ps1` / `capture54_v3.py` after source staging qualification. Earlier launcher attempts are preserved as execution history, not recommended entrypoints. For a fresh copy without a failed-attempt state file, launch `supervise54.py` directly from a persistent process with explicit log capture rather than copying the recovery entrypoint.

`qualify54_v2.py` checks the changed integration paths using only a fixed dummy observation array. Its two dummy EM iterations are excluded from formal results. The V1 prototype did not account for the upstream smoother's documented 1e-5 I correction; the V2 evaluator does.

Once all 12 fits have been sealed, run `evaluate54_v2.py` and `analyze54.py`. The server's `postprocess54_v1.py` waits for that seal and performs both steps automatically. It never reads heldout arrays before the seal. Train-only diagnostic readouts are sealed within the evaluator before heldout data are evaluated. Published raw metric JSON/CSV and hash receipts allow score auditing; signal arrays and weight files remain on server storage and are regenerated by the pinned generator/training seeds.

The full from-scratch 12-fit reproduction command sequence has not been run twice. The report describes the one completed execution only when its completion receipts exist. Prototype or failed-attempt code is retained for auditability and cannot be substituted for the qualified active evaluator.
