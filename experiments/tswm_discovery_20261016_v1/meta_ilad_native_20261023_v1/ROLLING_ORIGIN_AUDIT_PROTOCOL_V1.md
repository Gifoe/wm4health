# Rolling state estimation with the correct physical clock

Freeze before execution. This is a newly designed capability diagnostic, not an original paper reproduction, a context-transplant retuning, or an accepted novel direction. Preserve previous evidence. The previous context residual route is closed for method development.

Question: within the original trained time range, can the same native model reinitialize its state at a later observed window and retain useful forecasts? The refined source explicitly inputs absolute `t mod 2` to its force model. Correct absolute timestamps are available to every valid method. Resetting the clock is an intentionally incorrect negative control, never evidence against the model.

Use the already qualified original seed1000 checkpoint and complete original ID test input, with no new signal download or weight training. Use all75 environments, four query sequences per environment. Use the first11 trajectories from the native k_shot=12, seed42 support bank of13 trajectories; exclude all13 support indices from query selection. For each environment in order, sample four distinct allowed query indices using one NumPy default_rng seed202610234, then sort them. This gives300 sequences. The support bank contains completed independent episodes, not future observations from a query.

At origins0,5,10,15,20 (dt0.1), observe only that query's frames origin..origin+2. Predict20 frames beginning at the first observed frame; score only relative3..19. Every scored absolute time is <=3.9, so this does not confound the audit with time extrapolation beyond the trained40-frame window. Do not infer clock phase from images: it is known.

Hold the amortized posterior-mean environment code from the same11 support trajectories fixed. Four primary paths: (A) reencode the three-frame window, integrate using correct absolute times; (B) same code, fit only the two-dimensional query initial state with60 Adam0.01 updates, clip10, select per-query lowest observed-prefix loss including step0, then integrate at absolute times; (C) carry the native initial state inferred at time0 through one continuous40-frame rollout, taking the matching window, with no new observations; (D) same reencoded state as A, deliberately reset integration time to0. D is a negative control only. C uses a different observation history; its error cannot be advertised as a fair same-information new method.

No context-code refinement, hyperparameter search, future-based selection, rejection of hard queries, or physical-state labels as model inputs. Record all origins, every query, every prefix-loss trace and selected step. Model weights remain unchanged. There are300 queries with five repeated origins, not1500 independent systems. Origins change the physical state distribution, so a raw error increase versus origin0 is not alone a failure attribution.

Numerical controls: replay A versus D at origin0; independently restart carried latent trajectories at each absolute origin and compare their decoded windows to the unbroken rollout. Predeclared numerical tolerance1e-4 maximum pixel error. If this restart qualification fails, retain it as a solver/clock-lattice issue and do not interpret it as a learned state-semantic failure. Scores may remain descriptive, but require independent metric and input-selection verification before scientific interpretation. Do not widen this tolerance based on outcomes.

Retain original source hashes, checkpoint/data/protocol hashes, exact times, support/query indices, full images/latents and terminal execution/log-SHA receipts. Arrays stay in the authorized G-disk project; GitHub receives compact source, protocol, metrics, CSV and receipts only.
