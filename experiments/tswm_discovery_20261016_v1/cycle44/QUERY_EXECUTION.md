# Query execution detail — fixed allocations, no new model

This implements the already frozen protocol. Selected weights, VAL allocations and all five TRAIN-defined functions stay fixed. All16 models and first4 EVAL histories/model are included. Use16384 independently seeded fitted-law reference draws/history. SPF reference uses full fine paths; AR reference uses the qualified conditional-noise readout (same expectation, reduced variance); LGSSM uses the qualified16D spatial-mean Gaussian for smoothmax/crossing and exact fitted-law expectations for mean/roughness/occupancy. Record reference SE; exact learned-law expectations do not imply zero true-process bias.

Generate16 independent replicate pools/history, disjoint seeds from references and independent coarse terms. Reuse prefixes of each replicate's pool across budgets128/512/2048 and the five functions. This induces correlation across reported policies/budgets, not within a replicate's iid mean; retain this pairing and never count the budgets/functions as independent experimental replications. Save function arrays and exact seed recipes, not massive reference trajectories.

MC and antithetic MC are always scored. The VAL-selected ordinary policy is scored even when it duplicates a baseline. Include exact LGSSM expectations as a separate strong control wherever mathematically available, including a finite-pilot variance tie that may have selected a sampled policy. Do not retune allocations or select a new method from EVAL outcomes. Report all functions, including negative/trivial controls.

Per-block synchronized generation, all-five-function evaluation and CPU-transfer timings are retained for the executed pools. Those timings are constituent calls, not the latency of deploying each pooled policy. Additionally run dedicated complete requests at fixed EVAL history0/model for every distinct (policy,n0,n1) used by the three budgets/baselines. Clear per-history prefix caches per request; include warmup of deterministic history features, required coarse/moment setup, all generation, all-five-function evaluation, result transfer and reduction. Model construction/load is recorded separately as service initialization, not hidden in a per-request denominator. Store actual complete latency rather than replacing it with a variance-cost formula. History0 timing is not a claim that every history/domain has identical latency.

Calibration is an ordinary VAL expense, reported amortized over1/100/1000 single-function requests. The existing pilot measured all five functions per draw; the query evaluator retains that common charge, rather than claiming an optimized single-function kernel. Pool generation time and fitted-reference generation time are separate experimental expenses. No score may be claimed to support a new framework until independent query arithmetic, reference uncertainty, truth numerical accuracy and full-law quality have been checked.
