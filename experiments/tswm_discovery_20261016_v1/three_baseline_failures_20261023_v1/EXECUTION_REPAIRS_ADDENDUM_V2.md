# Execution corrections and attribution boundaries

This supplements the preserved V1 incident note. The V3 controller's recovery check attempted strict UTF-8 decoding of a log containing Windows console bytes and failed before creating further scientific workers. V4 checks the ASCII completion marker as bytes. It recovered the already completed first V2 worker without rerunning it and captured the remaining five workers normally. The missing first worker process-exit receipt remains explicitly null; numeric and artifact verification do not fabricate that receipt.

An observation helper also initially assumed all console text was UTF-8. Subsequent reads used replacement decoding and UTF-8 output. An inspection error is not a failed scientific run and did not authorize duplicate launches.

The fixed100 adapters deliberately ignore the early-stop **break**. Their inherited module docstrings and adapter `changes` list describe only the seed/storage portion; those labels are incomplete for this follow-up. The registered fixed-cap protocol, actual source diff, `run_type=fixed100_epoch_attribution_control`, `early_stop_break_ignored=true`, 100-row histories, and numeric verifier define the experiment. Its model and loss remain native, but the executed stopping rule is adapted. Do not describe it as unchanged paper reproduction.

Native raw and latent fits have equal forecasting-head parameter counts, not equal function classes: the latter includes a nonlinear frozen encoder and decoder. Matching update counts also does not match actual starting tensors, AE overhead or FLOPs. These remain distinct attribution issues.

The old C71 evaluator was recovered using a persistent CIM process with the unchanged evaluator and frozen protocol. Its original execution-environment guard failure and unsuccessful direct shell launch remain retained. No shorter evaluation budget or retraining is substituted for slow progress. The evaluator is a historical commitment, outside the three primary papers.
