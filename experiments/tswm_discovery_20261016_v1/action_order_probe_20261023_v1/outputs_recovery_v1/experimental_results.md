# 行动顺序诊断：朴素的顺序丢失解释被否定

四个既有模型、64条既有开发轨迹、两类动力系统、三种固定顺序编辑和identity负控，训练更新0。基础预测与各原保存数组最大差均0；模拟器identity重放最大差1.91e-06，通过原1e-5门槛。原始失败的预检和独立恢复回执均保留。

## 抽象行动确实包含顺序信息

| 编辑 | 仅行动重排、时间戳槽位固定：最大变化 | 行动与时间戳一起重排：最大变化 |
| --- | ---: | ---: |
| identity | 0.000000000 | 0 |
| swap_outer | 0.664704263 | 1.79e-07 |
| swap_middle | 0.275136530 | 1.79e-07 |
| reverse_blocks | 0.701941609 | 1.79e-07 |

原生MTS3把窗口内时间戳与行动拼接后编码；其Gaussian aggregation对带时间戳的二元组作集合聚合。重排二元组当然可以不变，但将行动移到不同时间槽会改变表示。完整模型还在fast path接收逐步行动。因此不能把这一架构说成天然只看行动直方图，也不能据此直接发明所谓顺序恢复模块。

剩余误差并不小，但不能由一颗seed、原1000更新和已用于事实选模的开发bank，判定为架构信息瓶颈。模型间两系统表现有差异，不能挑单个有利格宣布新方法必要性。没有按编辑结果重选epoch、修改动作或者打开reserved EVAL。

## 研究决定

否定“原生时间聚合必然抹去行动顺序”的朴素解释。保留响应误差，但不继续以该解释追加新架构或同组调参。原C88 anticipation修复路线保持其既有关闭结论。已有Log-NCDE/rough-path压缩、HWM learned action编码是强近邻；简单添加timestamp、GRU或signature本身不是本轮新贡献。

独立Torch CPU复核256个scalar，最大差3.12e-09；factual/edited MSE允许保存float32减法次序的1e-6差，响应量按1e-10核对。原源码、数据、checkpoint、协议与预测payload哈希复核。

当前接受新颖方向0，整体研究目标ACTIVE/UNACHIEVED。下一条值得资格检查的候选来自既有DALI线索：同一latent context编辑，能否在不同起点和不同后续行动下由一个固定的真实动力学参数变化解释？这是待实证的机制编辑问题，不是本轮已验证缺口。原生源码与checkpoint可行性先检查，禁止用未训练的toy模型冒充论文失败。
