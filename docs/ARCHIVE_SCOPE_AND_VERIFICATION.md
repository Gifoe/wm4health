# 归档范围与验证方式

本次汇总发布到 `Gifoe/wm4health`。服务器为原始证据来源；本地只编写汇总文字与发布控制代码。信号数据、权重、完整预测/latent 数组和长日志没有同步到本地，也没有加入此次提交。

## 保留与新增

- 保留仓库原有实验、C49/C52–C90 的已发布快照及原有 VitalDB 文件。
- 补入此前未发布的 C2–C48 紧凑报告与自编代码、配置、测试和允许的汇总指标。C1 根目录历史记录单独存为 `cycle01_historical`，因为它曾累计插入后续轮次的进度前言，不能视为纯净独立 C1 结果。
- 保留两个命名 addendum；C50/C51 没有独立目录，不虚构两个实验。
- 新增六个早期时序项目，以及一个明确标为非时序的 Long-Horizon Loop Dependency 支线。
- 新增人工汇总、逐阶段索引、机器目录、最新状态和逐文件清单。旧的研究判断不被批量重写；发生冲突时以最新总览和具体完成后的 closure/decision 为准。

## 文件选择

纳入 UTF-8 报告、研究代码、配置、复现说明、license 文本、允许的紧凑 CSV/JSON。原项目内完整第三方 clone、虚拟环境、数据、checkpoint、二进制 payload、原始长日志和图像不在本次补档范围；少量过大文本也被限制。因此历史报告中指向图像、完整环境、权重或大数组的链接可能只在服务器原目录成立，不表示文件丢失或已上传。

新增汇总和索引中的仓库内链接在发布前逐项核对。原始历史报告的所有外链和 server-only 附件没有重新下载或逐条重新验证。原始第三方实现仍需依各项目复现说明获取指定上游版本和依赖；这不是无需上游与数据的自包含软件发行包。

## 哈希与发布检查

`RESEARCH_ARCHIVE_MANIFEST_20261019.json` 记录本次补档文件的原始 SHA-256、发布 SHA-256、字节数与 Git blob SHA-1。仅在文本含个人 home 路径或服务器地址时做明确的隐私替换，并记录 `privacy_redaction=true`；研究 Python 文件保留原字节。凭据字面量扫描遇到可疑文件会阻止纳入并在跳过清单登记，绝不把凭据作为研究附件上传。

发布采用现有 main 的树为基础，只增加清单内文件并更新汇总入口/当前状态，不强制改写历史。每个新增 blob 与清单比对；原有非本次修改文件的 blob 必须保持不变；main 更新后再次核验提交和完整树。机器目录中的旧发布报告使用原 GitHub blob 身份，新增报告记录服务器原始哈希，避免将服务器工作稿误标为原发布版本。

这轮验证确认的是**归档来源、内容与导航**。它不等于重新训练所有模型，也不消除每轮报告已披露的训练预算、单 seed、VAL 选择、数据覆盖和数值参考限制。
